# Builder

The builder is the full console: object structure, select list, WHERE, child hops, sort, execute, results.

## Object structure

Search in the top bar (Enter). Pick a hit. Schema load fills parent attributes and relationships from `maximo_get_metadata`.

## Fields

Parent columns, Suggested chips (CORE + intent tokens, not the LLM), search, `*`. Child panels repeat the same picker per hop.

## Filters

- **WHERE** on the parent (`where.conditions`). Optional OR mode.
- **Timeline** - relative window on a date attribute (for example `-3M` on `changedate`).
- **Domain internal** - `domaininternalwhere` for coded values such as status.
- **Child options** - relationship, optional `path` for nested hops, child WHERE, child search. Each hop sends `childOptions.limit` (default **50**) so `maximo-mcp-server` does not warn and silently cap nested fetches. Change the number on that hop, or **No cap** (`noLimit: true`). This matches current `ChildOptionSchema` (`path`, `limit`, `noLimit`, `searchTerms`, `domaininternalwhere`, ...), not the old flat `{relationship: {where: "string"}}` shape.

Parent WHERE with a dotted field (`asset.priority = 2`) is an EXISTS filter on related parents. Child-options WHERE trims which nested rows load. They are not the same thing.

## Run

Execute calls `os_query_builder`, then `ws_load` / `ws_get_records`. Results search is Maximo `searchTerms` (Enter or Search re-runs). Load more uses a larger page, not a separate API.

Live execute re-runs as you edit; it pauses if you leave the builder via Back.

When Query and Results are both visible, drag the split between them. Double-click the handle to reset.

## Results Excel

From the results table, download an `.xlsx` (ExcelJS). Options stay on that dialog; they are not stored on the query.

Excel cannot nest a child table inside a parent cell the way the results tree does. Default layout is **one sheet per relationship**:

- The parent sheet is parent columns only (no Level / Path / ParentKey).
- A child name cell (`2 rows` / `Open`) jumps to that parent's first row on the child sheet.
- Child sheets have a **Parent** link back. Nested hops get the same click-through.
- After you jump, rows for that parent sit together; use the Parent column AutoFilter to keep one parent.

Same-sheet outline (blank ancestor cells + Excel grouping) and flat leaves (parent columns repeated) are still available for PivotTables.

Print is always landscape, with repeating titles and a Generated by mxQuery footer. Do not combine ExcelJS `fitToPage` with row grouping - Excel refuses to open that file.

## Import

Paste `os_query_builder` JSON (the arguments object, or `os_query_builder({...})`) or an OSLC GET URL. Lean/paging query params that are not part of the tool call are dropped. Nested `rel.NAME{...}` select is hydrated against live schema after import.

Dotted parent WHERE (`asset.priority`) unfolds into **FILTER PARENTS BY RELATED** hops. Unresolved dotted paths stay on parent WHERE. `childOptions` WHERE still lands on the matching nested hop (for example OPENWO `istask=0` on ASSET -> ASSET_PARENT -> OPENWO).

## Save and report

Save writes to this tenant's library (folder or Stash). Open a saved query as builder, results, or **report** (`/builder/report`) - report is display-only (no Save / maximize chrome).

Display flatten, table layout, and charts are stored with the query JSON as client display config. They are not extra MCP tools. Excel export is results-only, not part of that JSON.
